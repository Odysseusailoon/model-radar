你在为一家公司做招聘人才 mapping。请只输出 JSON。

【公司背景】【填空:公司名】,【填空:一句话业务定位——候选人看了会不会心动,
取决于这句写得实不实】。【填空:1 句团队/融资亮点,核实过再写。】

在招方向:【填空:列 2-4 个方向,每个写清楚——职位 / 需要什么背景 / 加分项。
例:研究员(方向 X,需要一作论文)、资深工程师(做过 Y 系统)、创始 GTM。】

【判定任务】对每个 X 账号,判断此人是否是在招方向的潜在候选人,或是能推荐
候选人的节点(该方向的导师、社区组织者)。

tier 取值:
  3 = 强相关。bio 显示其当前就在做【填空:在招方向】之一,且身份明确
      (在职研究员/工程师/PhD,写明了方向或代表作)。
  2 = 中相关。相邻方向、或背景对口但资历深浅看不准;或是该方向的导师/
      实验室负责人/社区组织者,可作为推荐节点。
  1 = 弱相关。泛行业从业者,方向交集间接。
  0 = 无关。行业无关、bio 看不出方向、或为公司官方号/营销号。

category 取值(单选,对应在招方向,key 按需增删,但必须与 config.json 一致):
  role_a(【填空:方向一,例 research】) / role_b(【填空:方向二,例 engineering】) /
  role_c(【填空:方向三,例 gtm】) / referrer(导师/社区节点,可推荐人) / other

reason:一句中文,不超过 42 字,必须说清其背景与哪个在招方向匹配、匹配点是什么,
要引用 bio 里的实际信息(现职、方向、代表作)。禁止空话。拿不准就给低 tier。
注意:**不要根据姓名猜测任何人的国籍、性别或年龄**,只用 bio 里写明的信息。

输出:一个 JSON 数组,顺序与输入完全一致,每个元素形如
{"handle":"...","tier":0,"category":"...","reason":"..."}
只输出 JSON 数组,不要解释、不要代码块标记。
